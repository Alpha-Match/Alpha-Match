### 2. DB 초기화 및 마이그레이션 실행

**문제:**
- Flyway auto-migration이 Bean 초기화 전에 실행되지 않음
- `relation "checkpoint" does not exist` 오류 발생

**해결:**
- `reset_db.sql` 생성: DB drop/create + pgvector 설치
- `reset_db.bat` 생성: Windows 환경 스크립트
- `run_migrations.bat` 생성: V1, V2 수동 마이그레이션 실행
- 성공적으로 모든 테이블 생성 완료

**생성된 파일:**
```batch
# reset_db.bat
@echo off
set PGPASSWORD=<DB_PASSWORD>
psql -h localhost -p 5433 -U postgres -d postgres -f reset_db.sql

# run_migrations.bat
@echo off
set PGPASSWORD=<DB_PASSWORD>
psql -h localhost -p 5433 -U postgres -d alpha_match -f src/main/resources/db/migration/V1__init_schema.sql
psql -h localhost -p 5433 -U postgres -d alpha_match -f src/main/resources/db/migration/V2__restructure_schema_to_v2.sql
```

### 3. Quartz Scheduler 설정 문제 해결

**문제:**
- `org.quartz.SchedulerConfigException: DataSource name not set`
- Spring Boot 4.0에서 QuartzProperties, @QuartzDataSource 미지원

**시도한 해결 방법:**
1. ❌ Quartz DataSource 명시적 설정 (org.quartz.dataSource.* 프로퍼티)
2. ❌ QuartzConfig.java 생성 (SchedulerFactoryBean with DataSource)
3. ❌ Spring Boot auto-configuration 활용

**최종 해결:**
- Pattern 1 (Server Streaming with Scheduler)이 비활성화되어 있으므로 Quartz 전체 비활성화
- `application.yml`에서 `quartz.auto-startup: false` 설정
- QuartzConfig.java 삭제
- RAMJobStore 사용 (JDBC JobStore 대신)

**변경 사항 (`application.yml`):**
```yaml
# 기존 (복잡한 JDBC JobStore 설정)
quartz:
  job-store-type: jdbc
  properties:
    org.quartz.jobStore.class: org.quartz.impl.jdbcjobstore.JobStoreTX
    org.quartz.jobStore.dataSource: quartzDataSource
    # ... 많은 설정

# 변경 후 (간소화)
quartz:
  auto-startup: false  # Quartz 자동 시작 비활성화
```

## 🔄 아키텍처 결정 사항

### Pattern 1 vs Pattern 2

**Pattern 1 (Server Streaming):**
- Batch Server → Python Server 요청
- Quartz Scheduler 기반 정기 실행
- **현재 비활성화** (`batch.scheduler.jobs.*.enabled: false`)

**Pattern 2 (Client Streaming):**
- Python Server → Batch Server 전송
- FastAPI 엔드포인트 트리거 시 즉시 실행
- **현재 활성화** (gRPC Server 포트 9090 대기 중)

### Quartz 비활성화 이유

1. Pattern 1이 비활성화되어 있어 스케줄러 불필요
2. Pattern 2만 사용하는 현재 전략에서는 Quartz JDBC JobStore 설정 불필요
3. Spring Boot 4.0 호환성 문제 해결
4. 시스템 복잡도 감소

## 💡 교훈

### Flyway vs Manual Migration

**문제:**
- Spring Boot 초기화 순서: Bean Factory → Flyway Migration
- Bean 생성 시 DB 조회 → 테이블 없음 오류

**해결 옵션:**
1. `@DependsOn("flyway")` 사용 (복잡도 증가)
2. Lazy initialization (일부 기능만 해결)
3. **수동 마이그레이션 스크립트** (선택됨 - 명확하고 제어 가능)

### Spring Boot 4.0 Quartz 통합

- QuartzProperties, @QuartzDataSource 같은 편의 기능 제거됨
- JDBC JobStore 설정 시 수동 DataSource 연결 필요
- 불필요한 기능은 비활성화하는 것이 최선
